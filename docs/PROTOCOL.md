# 控制协议

### FSV2 视频通道

视频通道使用 Unix `SOCK_STREAM`。每个 H.264 access unit 都以固定 80 字节
协议头开始，后面紧跟恰好 `payload_size` 字节的负载。整数字段使用网络字节序。
C/C++ 结构体内存布局不属于协议。

| 偏移 | 大小 | 字段 |
| ---: | ---: | --- |
| 0 | 4 | 魔数 `FSV2` |
| 4 | 2 | 协议版本，当前为 `2` |
| 6 | 2 | 协议头大小，当前为 `80` |
| 8 | 4 | 串流 ID |
| 12 | 4 | 串流 generation |
| 16 | 8 | 数据包序列号 |
| 24 | 8 | 显示时间戳，单位微秒 |
| 32 | 4 | 数据包标志 |
| 36 | 4 | 编码格式 ID；H.264 为 `1` |
| 40 | 4 | 传给视频编码器的编码宽度 |
| 44 | 4 | 传给视频编码器的编码高度 |
| 48 | 4 | Android 逻辑显示宽度 |
| 52 | 4 | Android 逻辑显示高度 |
| 56 | 4 | 负载大小 |
| 60 | 4 | 顺时针显示旋转角度：`0`、`90`、`180` 或 `270` |
| 64 | 8 | 帧提交时的 `CLOCK_MONOTONIC` 纳秒时间戳，无对应帧时为零 |
| 72 | 8 | 保留字段，必须为零 |

接收端对解码后的编码像素顺时针应用 `display_rotation`，恢复 Android 逻辑方向。
例如，逻辑 `720x1280` 屏幕以编码 `1280x720` 和旋转 `90` 发送。容器把最终显示
缓冲区绘制到编码器输入 Surface 时执行相反的逆时针旋转。旋转融合在现有 EGL
绘制中，不会增加一次额外的全帧复制。

Android 输入始终使用逻辑尺寸坐标系。编码尺寸只描述解码器输出，不能直接用于
触摸坐标。旋转 `90` 或 `270` 度时编码画幅宽高转置，其他旋转保持逻辑画幅。

数据包标志用于标识编码配置、关键帧、流结束和不连续。分辨率变化会递增串流
generation，随后发送新 generation 的编码配置和关键帧。

串流会话接受输入帧时记录提交时间戳。宿主接收完整负载后记录
`CLOCK_MONOTONIC`，两者相减得到“提交至宿主”的延迟。没有输入帧对应的编码
配置包和流结束包使用零时间戳。直接比较之前，必须确认容器和宿主单调时钟属于
可比较的时钟域。

`HostVideoSink` 持有有界异步队列。队列饱和会返回调用者，不会阻塞编码器线程。
会话管理器负责丢弃依赖帧、请求 IDR，并把下一个可恢复数据包标记为不连续。

### FHC1 控制通道

控制通道使用双向 Unix `SOCK_STREAM`。宿主默认监听
`/mnt/vendor/floral_stream/control.sock`，容器主动连接。每条消息以固定
24 字节协议头开始，整数字段使用网络字节序。

| 偏移 | 大小 | 字段 |
| ---: | ---: | --- |
| 0 | 4 | 魔数 `FHC1` |
| 4 | 2 | 协议版本，当前为 `1` |
| 6 | 2 | 协议头大小，当前为 `24` |
| 8 | 2 | 消息类型 |
| 10 | 2 | 标志，必须为零 |
| 12 | 4 | 非零请求 ID，响应原样返回 |
| 16 | 4 | 负载大小，最大 65536 字节 |
| 20 | 4 | 保留字段，必须为零 |

消息类型 `0x0100` 用完整期望快照替换外屏拓扑，响应类型为 `0x8100`。未知请求
收到通用 `0x8000` 错误响应。完整快照使重连操作保持幂等，并消除增量添加和删除
命令之间的顺序依赖。

替换拓扑负载以以下字段开始：

| 偏移 | 大小 | 字段 |
| ---: | ---: | --- |
| 0 | 4 | 外屏数量，最大 64 |
| 4 | 4 | 保留字段，必须为零 |

随后每个显示器使用一条变长记录：

| 偏移 | 大小 | 字段 |
| ---: | ---: | --- |
| 0 | 4 | 记录大小，包含补齐到 4 字节的零填充 |
| 4 | 8 | 显示器 ID；0 和 1 为保留值 |
| 12 | 4 | 物理端口，范围 1 至 255 |
| 16 | 4 | 逻辑宽度 |
| 20 | 4 | 逻辑高度 |
| 24 | 4 | DPI 密度 |
| 28 | 4 | 当前刷新率，单位 Hz |
| 32 | 2 | 支持的刷新率数量，最大 16 |
| 34 | 2 | UTF-8 显示器名称字节数，最大 128 |
| 36 | 变长 | 以 32 位整数表示的刷新率列表 |
| 后续 | 变长 | 不含结尾空字符的显示器名称 |
| 后续 | 0-3 | 计入记录大小的零填充 |

16 字节 `0x8100` 响应包含 32 位结果、一个值为零的保留字和最终 64 位拓扑
generation。结果值分别是：`0` 已应用、`1` 未变化、`2` 显示器无效、`3`
显示器 ID 重复、`4` 端口重复、`5` 控制器不可用。

成功应用或内容相同的快照都会续期控制权。Socket 断开后，外屏在配置的三秒租约
内继续保留。重连后收到有效完整快照会取消待执行的过期操作；内容相同时不会改变
generation。租约到期后，控制器发布空外屏快照。FHC1 不表示主屏，也不能通过
该通道移除主屏。
